# EOL 검사 불량 집계 자동화 정리

근거: [업무 분해 시트](./eol-defect-worksheet.md), [확정 규칙](./eol-defect-rules.md), [스킬](../.github/skills/eol-defect/SKILL.md), [스크립트](../scripts/eol-defect.js), [검증셋](../tests/eol-defect-cases.json), 이번 실행 결과.

## 1. 과제

| 항목 | 내용 |
| --- | --- |
| 업무 | EOL 검사 기록에서 시리얼별 최종 검사 결과를 판정하고 월별 불량 제품 수와 최다 불량 월을 집계 |
| 주기와 걸리는 시간 | 입력은 연간 기록이나 실행 주기와 처리 시간은 확인 필요 |
| 지금 방식 | 엑셀에서 불합격 행을 필터링한 뒤 월별 불량 제품 수를 집계 |
| 문제 | 기존 방식에서 발생한 실수·누락 사례와 처리 시간은 확인 필요 |
| 완성 기준 | 검증셋이 모두 일치하고, 집계가 확정된 경우 월별 표·최다 월·제외 및 판정 불가 내역을 결과 파일에 기록. 이번 실행은 이 기준을 충족함 |

## 2. 업무 분해와 판단 기준

| 순서 | 하는 일 | 판단 기준 | 맡길 곳 |
| --- | --- | --- | --- |
| 1 | 입력 범위와 규칙 확인 | `practice/eol-results.csv` 전체를 대상으로 하고 원본은 수정하지 않음 | 사람 |
| 2 | CSV 구조와 값 검사 | BOM·인용 필드를 읽고 필수 열, 중복 열, 행별 열 수를 검사 | 스크립트 |
| 3 | 제외 및 검사 구성 | 시리얼이 `MST`로 시작하면 제외. 같은 시리얼·검사번호를 한 검사로 구성. 측정값이 정확히 `ERR`인 행은 측정 판정에서 제외 | 스크립트 |
| 4 | 최종 검사 선택 및 판정 | 시리얼별 검사시각이 가장 늦은 검사를 선택하고, 시각이 같으면 검사번호 자연 정렬 순서 적용. mV를 V로 변환하고 하한·상한을 포함해 판정 | 스크립트 |
| 5 | 월별 집계와 검증 | 최종 검사 월에 불량 시리얼을 중복 없이 집계하고 검증셋 기대값과 실제값을 대조 | 스크립트 |
| 6 | 결과 검토 및 요약 | 생성된 결과만 인용하고 판정 불가와 확인 필요 사항을 표시 | 모델, 사람 |
| 7 | 품질 파트장에게 전달 | 내용·대상·채널·검증 상태를 먼저 확인하고 명시적으로 승인된 범위에서만 전달 | 사람 승인 |

- **입력 파일:** `practice/eol-results.csv`. 열은 `검사번호`, `검사시각`, `라인`, `시리얼`, `검사항목`, `측정값`, `하한`, `상한`, `비고`. 경로상 연습 데이터인지 실제 업무 데이터인지는 확인 필요합니다. 검증셋은 같은 형식의 가짜 데이터를 사용합니다.
- **판정 기준:** 음수는 유효한 수치이며, `mV`는 1000으로 나눠 V로 비교합니다. 유효 측정 항목 중 하나라도 범위 밖이면 해당 검사는 불합격입니다. 라인이 달라도 같은 시리얼은 같은 제품입니다.
- **판정 불가:** 마지막 검사에 유효 측정값이 없거나 시각·수치·한계값·식별값 등에 문제가 있으면 임의로 제외하거나 이전 검사로 대체하지 않습니다. 판정 불가 제품 또는 식별 불가 행이 있으면 집계를 확정 보류하고 종료 코드로도 알립니다.
- **확인 필요:** 실행 주기와 처리 시간, 필수 검사항목 목록, 입력 파일이 실제 현장 자료인지 여부, 과거 수작업의 문제 사례는 제공된 파일에서 확인되지 않습니다.

## 3. 설계

| 파일 | 역할 |
| --- | --- |
| [업무 분해 시트](./eol-defect-worksheet.md) | 업무 범위, 단계, 담당 경계 및 결과물 정의 |
| [규칙 문서](./eol-defect-rules.md) | 입력·제외·최종 검사·판정·월 귀속 기준 |
| [스크립트](../scripts/eol-defect.js) | CSV 파싱, 검증셋 실행, 검사 판정, 월별 집계 및 결과 파일 생성 |
| [스킬](../.github/skills/eol-defect/SKILL.md) | `/eol-defect` 실행 순서, 결과 검토 및 전달 승인 절차 |
| [검증셋](../tests/eol-defect-cases.json) | 정상·경계·판정 불가 상황에 대한 가짜 입력과 기대 결과 |
| `output/eol-defect-check.json`, `.md` | 케이스별 기대·실제값 및 일치 여부 |
| `output/eol-defect-profile.json` | 입력의 검사시각·측정값 형식 프로파일 |
| `output/eol-defect-result.json`, `.md` | 집계, 최다 월, 제품별 판정, 제외 및 판정 불가 근거 |
| `output/eol-defect-comparison.json`, `.md` | 선택 실행에서 참고값과 총 불량 수·최다 월을 비교 |

- **실행 흐름:** `node scripts/eol-defect.js`는 먼저 검증셋을 실행합니다. 불일치하면 집계를 진행하지 않습니다. 일치하면 CSV를 읽고 프로파일과 집계 결과를 `output/`에 기록합니다. `--check`는 검증만 수행하며, `--compare`는 인자로 받은 참고값 비교 결과를 추가로 기록합니다. 참고값 비교는 상시 판정 기준이 아닙니다.
- **사람 확인·승인:** 판정 불가나 미확정 기준을 검토하고, 품질 파트장에게 보낼 내용·대상·채널·검증 상태를 확인합니다. 승인 전 외부 전송은 하지 않습니다.
- **핵심 지시문:** 현재 스킬은 사용자가 `/eol-defect`로 호출할 때 실행되며 결과 숫자는 스크립트 출력만 사용하도록 합니다. 최초 요청과 수정 요청의 전체 이력은 문서 및 결과 파일에서 확인할 수 없어 확인 필요합니다.

## 5. 팀 적용

- **누가, 어떤 주기로, 어떤 입력을 넣는지:** 실행 담당자와 주기는 확인 필요. 실행 시 `practice/eol-results.csv` 경로의 EOL CSV를 사용합니다.
- **팀원에게 공유할 것:** 저장소의 해당 업무 파일, 입력 파일 위치 `practice/eol-results.csv`, 실행할 스킬 이름 `/eol-defect`. 팀의 저장소 접근 권한과 배포 방법은 확인 필요합니다.
- **사내 Copilot에서 미리 확인할 것:** 저장소 스킬 인식 여부, 실행 담당자의 입력 파일 접근 권한, 결과 저장 경로 접근 권한 및 사내 정책상 데이터 사용 가능 여부는 확인 필요합니다.
- **기대 효과:** 기존 엑셀 필터링·월별 집계를 스크립트로 반복 가능하게 하고 검증 결과와 근거를 파일로 남깁니다. 처리 시간 절감, 실수·누락 감소 효과의 실제 크기는 측정 자료가 없어 확인 필요합니다.

## 6. 운영과 남은 일

- **관리 담당자와 기준 변경 절차:** 담당자는 확인 필요합니다. 기준 변경 시 승인 책임자와 배포 절차도 확인 필요합니다. 실행 시 검증셋을 먼저 통과해야 실제 집계가 진행됩니다.
- **아직 확인이 필요한 기준:** 필수 검사항목 및 항목 완전성 기준, 운영 주기, 입력 자료의 실제/연습 구분.
- **자동화하지 않은 단계와 이유:** 기준이 모호한 경우의 확정, 보고서 검토, 품질 파트장 전달 승인 및 실제 전송은 사람의 확인이 필요합니다. 전달 채널은 확인 필요합니다.
- **팀원이 쓰기 전에 알아야 할 한계:** 파일에 들어 있는 기록만 집계하며 파일 밖 이력은 조회하지 않습니다. 필수 검사항목 누락을 검출하지 않으며, 최종 검사에서 판정 불가가 발생하면 이전 검사로 대체하지 않습니다. 참고값 비교는 총 불량 수와 최다 월만 대조하므로 월별 표 전체의 독립 검증을 대신하지 않습니다.
