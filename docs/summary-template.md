# 자동화 정리 문서 양식

자동화를 마친 뒤 팀에 넘길 정리 문서의 형식입니다.
`docs/<영문 이름>-summary.md`로 복사해서 작성하며, 각 칸은 만든 파일과 실행 결과에서 확인한 내용만 적습니다.
파일에서 확인할 수 없는 칸은 '확인 필요'로 남기고 업무를 아는 사람이 직접 작성합니다.

## 1. 과제

| 항목 | 내용 |
| --- | --- |
| 업무 | 자동화한 반복 업무 |
| 주기와 걸리는 시간 | 얼마나 자주 하고 한 번에 얼마나 걸리는지 |
| 지금 방식 | 지금 사람이 처리하는 순서 |
| 문제 | 실수, 누락, 사람마다 다른 결과처럼 지금 방식의 문제 |
| 완성 기준 | 어디까지 되면 완성으로 볼지 |

## 2. 업무 분해와 판단 기준

| 순서 | 하는 일 | 판단 기준 | 맡길 곳 |
| --- | --- | --- | --- |
| 1 | | | 사람, 스크립트, 모델 중 하나 |

- 입력 파일: 형식과 열 이름, 가짜 데이터나 연습용 데이터인지
- 판단 기준: 숫자, 조건, 경계값이 어느 쪽에 속하는지
- 판정하지 않는 경우: 판정 불가나 미판정으로 남기는 조건과 표시 방법
- '확인 필요'로 물어본 항목과 답

## 3. 설계

| 파일 | 역할 |
| --- | --- |
| 규칙 문서 | |
| 스크립트 | |
| 스킬 | |
| 검증셋 | |

- 실행 흐름: 스킬이 실행하는 순서와 단계마다 만들어지는 파일
- 사람이 확인하거나 승인하는 곳
- 핵심 지시문: 처음 요청과 결과, 고친 요청과 결과, 결과를 바꾼 규칙

## 4. 검증 결과

| 확인 방법 | 결과 |
| --- | --- |
| 정답(수작업 결과)과 비교 | |
| 검증셋 | |
| 새 세션에서 다시 실행 | |

## 5. 팀 적용

- 누가, 어떤 주기로, 어떤 입력을 넣어서 실행하는지
- 팀원에게 공유할 것: 저장소, 입력 파일을 두는 위치, 실행할 스킬 이름
- 사내 Copilot에서 미리 확인할 것
- 기대 효과: 처리 시간, 실수와 누락, 결과물 형식의 전과 후

## 6. 운영과 남은 일

- 규칙 문서, 스크립트, 검증셋을 관리하는 사람과 기준이 바뀔 때 고치는 순서
- 아직 확인이 필요한 기준
- 자동화하지 않은 단계와 이유
- 팀원이 쓰기 전에 알아야 할 한계
