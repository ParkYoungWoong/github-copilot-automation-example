# 업무 분해 시트: 시험 결과 보고

반복 업무 하나를 단계로 나누고, 단계마다 누구에게 맡길지 정합니다.
새 업무는 이 형식을 복사해서 작성합니다.

## 업무 개요

| 항목 | 내용 |
| --- | --- |
| 업무 | 환경 시험 로그를 판정하고 결과를 보고 |
| 주기 | 시험이 끝날 때마다, 매주 금요일 정리 |
| 입력 | `data/test-cases.csv`, `data/logs/*.csv` |
| 결과물 | 판정표, 그래프 보고서, 요약, 결함 이슈 |
| 받는 사람 | 파트장, 시험 담당자 |

## 단계

| 순서 | 하는 일 | 판단 기준 | 맡길 곳 |
| --- | --- | --- | --- |
| 1 | 시험 PC에서 로그를 CSV로 내보내기 | | 사람 |
| 2 | 인코딩과 열 이름 맞추기 | 열 이름 표 | 스크립트 |
| 3 | 시험 항목마다 Pass, Fail 판정 | 허용 오차, 안정화 300초, 끊김 3초 | 스크립트 |
| 4 | 오차 그래프 그리기 | | 스크립트 |
| 5 | 요약과 다음 조치 작성 | 요약 형식 | 모델 |
| 6 | Fail 건 결함 등록 | 중복 이슈 확인 | 모델, 사람 승인 |
| 7 | 보고서 검토 후 공유 | | 사람 |

## 맡길 곳을 정하는 기준

| 이런 일 | 맡길 곳 |
| --- | --- |
| 같은 입력에 항상 같은 답이 나와야 하는 계산, 판정, 변환 | 스크립트 |
| 요약, 문장 작성, 분류 이유 설명, 빠진 정보 묻기 | 모델 |
| 외부로 보내기, 지우기, 되돌릴 수 없는 일 | 사람 승인 |

## 검증

| 확인할 것 | 방법 |
| --- | --- |
| 판정이 규칙대로인가 | `node scripts/check.js` 결과가 모두 일치 |
| 요약의 숫자가 맞는가 | `output/tc-result.md`와 대조 |
| 결함이 중복으로 등록되지 않는가 | 같은 TC로 두 번 요청해 보기 |
